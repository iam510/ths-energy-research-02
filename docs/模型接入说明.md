# MiniMax模型与研究更新接入说明

当前采用官方AI SDK Provider、MiniMax-M3.1-Flash及中国OpenAI兼容接口 https://api.minimax.cn/v1/chat/completions。提示词版本minimax-research-v7。密钥仅存在受忽略的本地app/.dev.vars与Sites服务端secret，不能写入客户端、GitHub或提交包。

订阅Key（sk-cp前缀）在“个人订阅→套餐管理”获取；按量Key在“API管理→API Key”获取，两者使用的计费资源不同，但当前模型和Base URL可以保留。官方参考：[M Plan其他工具](https://platform.minimax.cn/docs/m-plan/other-tools)、[常见问题](https://platform.minimax.cn/docs/m-plan/faq)。本项目未购买套餐或重置Key。

## 本地配置

```dotenv
MINIMAX_API_KEY=填写自己的订阅Key或按量Key
MINIMAX_MODEL=MiniMax-M3.1-Flash
MINIMAX_DAILY_LIMIT=30
```

在app/.dev.vars中配置，权限600；重新启动本地服务。生产通过Sites设置secret并重新部署，使环境修订生效。app/.env.example不含真实密钥。

## API与版本

- GET /api/research：版本、来源示例、配置及剩余额度，不含密钥。
- POST /api/research：保存候选，剥离自报metric、研究状态、环节和复核信用，不直接生效。
- POST /api/review：在当前空间复核生效或撤回；需当前版本、原文摘录、理由、来源确认、产品/规划/收入/财务背景进展及环节。每次产生新版本；可通过新材料取代当前空间的旧依据；公共种子原文及历史版本不修改。
- POST /api/analyze：mode为live时调用模型，offline时使用明确标注的规则；revision指定历史材料。返回activeStageIds和sourceIds，便于核对生效材料集合。
- POST /api/ai：比较与公开材料候选提取。仅当前版本的预置材料和个人复核生效材料可用于分析；撤回与未生效候选排除。

## 校验和剩余边界

确定性代码负责业务矩阵、指标表、资料版本和撤回；模型解释不是独立审计。每条AI比较项要求双方引用，陈述中公司必须与本条引用匹配，数值不能从其他引用借用，部分币种、年度和混合业务收入错误会被拒绝。比较解释不复述数字，指标仍由结构化来源表呈现。待验证节点如提及公司事实也需有引用。

这些规则尚不能判断所有语言语义、否定关系、因果强度或业务范围。新增材料的URL只校验官方域名，程序不会自动核对用户粘贴文本与远端正文；个人复核不等于来源获独立认证。导入时不保留自报指标；复核时须独立填写原值、单位、币种及范围，摘录须支持对应数值和单位。匹配通过仍是个人复核，不构成真实性认证。

材料提取只生成候选，短摘录检查是否出现在输入中，不能自动确认公司真实业务。上传文本会发送给MiniMax，请仅使用公开材料。

## 调用记录与额度

每次最多4096输出tokens、low思考深度、45秒超时、自动重试0次。默认全站每日30次、单空间每日8次、每分钟6次。日额度按北京时间重置，失败也计数。剩余次数不是提供商套餐余额，仍受提供商窗口和服务可用性约束。

ai_runs只保存任务、模型、提示词版本、来源ID、状态、用量及耗时，不保存密钥、原始提示词、全文或思考过程。未调用、失败或校验拒绝均不显示新的成功回执。历史真实样例有明确日期、原始运行ID及“非本次生成”标识。

早期HTTP402及接入阶段记录见history/AI接入阶段-模型接入说明.md，最新验收见测试说明及delivery/MiniMax接入验证.json。

最终比较策略：只有个别条目不符合公司、数值或口径校验时，移除该条并展示提示；至少保留一个有双方依据的可比项和一个有效边界，否则整次拒绝。无效结构、不存在引用及交易承诺仍整次拒绝。部分采纳在运行记录中标为partial，不能冒称全部输出通过。

本轮v7：不使用模型自由摘要；摘要由通过校验的首个可比项与边界项拼接。取代与撤回材料从当前AI输入排除；新增材料的个人复核摘录也传给模型。原文混合未来计划与实际进展时要求拆条，避免误授信。
