# 第二题实现规划

日期：2026-10-30。本文为开工前规划快照；实施后的实际状态、范围调整及验证结果以README、测试说明和提交清单为准。以下数量与工时为原计划，不是完成记录。

## 1. 题目理解与交付边界

本题要交付一个持续可更新的 AI 产业研究产品，主链路为：

**产业分层 → 公司业务归属 → 证据强弱 → 中外公司比较 → 外部变化传导 → 新证据更新研究结果。**

核心体验是帮助研究者回答“为什么这家公司属于这个环节、凭什么认为它受影响”，不能只展示概念股名单或生成无出处的研究报告。

原题明确要求：

- 收到题目后 48 小时内提交；实际收题时间尚未核定，不能把本文件日期直接当作截止时间起点。
- 可访问、可实际操作的 Web URL，源代码仓库及 README。
- 60–180 秒演示视频，AI 使用与验证记录，测试说明。
- 关键数字与结论可追溯。

用户要求最终上传整个 `02_产业链跨市场与公司研究/` 文件夹的压缩包。因此源码、数据说明、配置示例、部署记录、演示视频和交付索引均放在本文件夹内部；不修改根目录、01 或 03。仅提供压缩包还不足以替代原题要求的线上 URL、仓库和视频。

## 2. 建议选题和最小范围

建议方向：**电化学储能产业链与跨市场公司研究**，暂定产品名“储能研究台”。

选题理由是它能在一个有限范围内演示分层、跨环节经营、业务口径差异和成本/需求传导。现已初步验证以下官方公开入口可读取，证明至少部分样本有可追溯材料，并不代表已经完成全行业数据核验：

- [宁德时代 2025 年报发布说明](https://www.catl.com/en/news/6773.html)：包含储能业务相关说明；正式提取财务数据仍以年报原文为准。
- [Tesla 2025 Form 10-K](https://www.sec.gov/Archives/edgar/data/1318605/000162828026003952/tsla-20251231.htm)：包含储能产品说明及能源业务披露。其能源业务口径包含发电与储能，不能直接当作纯储能收入。

上述材料只验证数据路径。实施时检查最新可用披露，标明发布日期、报告期和资料截至日，不把 2025 年报称为“当前最新数据”。

第一版范围：

- 只做一个产业，目标覆盖 6–8 家公司、至少 2 家海外公司，预备约 25–40 条经核对的证据。
- 暂按“电芯与电池系统 / PCS 与控制 / 系统集成 / 项目运营及服务”划分业务环节；允许公司同时属于多个环节，不将这四类误画成严格串行的采购关系。
- 分类说明要写清纳入/排除标准、版本和来源；这是本产品采用的研究口径，不冒充同花顺官方分类。
- 候选池：宁德时代、亿纬锂能、阳光电源、科华数据、Tesla、Fluence、LG Energy Solution；是否纳入取决于实际证据与分部披露质量。
- 先确保两组有解释价值的中外业务比较，再考虑扩充数量。比较对象最终随证据核验确定，不在此预先认定其完全可比。
- 限定 3 类演示情景：原材料成本变化、海外贸易/政策变化、下游需求变化。实际事件和用户假设分开保存与展示。

不做第一版范围：全行业搜索、实时行情终端、荐股排行、收益预测、自动交易、大规模知识图谱和完整账户体系。

## 3. 页面与用户主流程

### A. 产业研究总览

显示分类口径、产业环节和公司列表；支持按环节、市场和证据状态筛选。首页直接提供一个可点击的研究示例，避免要求用户先会写提示词。

点击公司进入业务证据面板：业务归属理由、证据状态、报告期、相关指标、原文定位、来源链接和当前缺口。用户应能从每一个关键结论回到证据。

### B. 中外公司对照

选择两家公司，按业务/产品、客户及应用场景、区域、收入确认与财务口径逐项比较，分别显示“可比部分”和“不可比部分”。

每个指标记录币种、单位、统计周期和业务范围。缺少分部数据时显示“未披露”；不同报告期不直接计算同比；不把出货量、装机量、交付量混用。第一版优先保留原币，避免无可靠汇率时强行换算。

### C. 变化传导分析

选择真实事件或输入明确标记的假设，生成：

**外部变化 → 受影响环节 → 公司具体业务 → 财务指标 → 生效条件 / 反向因素 / 待验证指标。**

例如“假设电芯采购成本下降”，研究其对集成业务成本与毛利的可能影响，同时说明售价调整、合同锁价、存货和时间滞后可能改变结果。不得直接从原材料下降推导股价上涨，也不得无依据生成利润增幅。

每条路径节点标明“已披露事实 / 基于证据的推断 / 情景假设”，引用支持该节点的证据。数据不足时返回缺口，不补造结论。

### D. 更新与复核

展示数据截至时间、上次检查时间、更新状态和变更记录。支持通过受控数据源或结构化证据文件导入一条新材料，经过校验、去重、AI 提取、人工确认后生成新版本。

演示必须包含一次真实状态变化：新证据进入 → 某条业务关系或研究结论发生变化 → 历史版本仍可查。仅修改页面时间戳或刷新缓存不算持续更新。

## 4. 证据与可信度设计

将“业务进展”和“证据质量”分开，避免一个看似精确的 AI 分数掩盖差异。

业务进展采用可解释的类别：

| 类别 | 判定依据 | 展示边界 |
| --- | --- | --- |
| 已披露相关收入 | 正式披露明确的对应业务收入 | 业务口径不等于纯概念收入；不得外推未披露的占比 |
| 已有产品/交付/订单证据 | 官方材料明确产品、交付或订单 | 区分订单、交付、收入；不能相互替代 |
| 研发/规划/表态 | 官方披露研发、规划或布局 | 不推定已经商业化 |
| 当前未检得有效证据 | 在明确的资料范围内未找到支持 | 标出搜索范围和截至日；不等于断言公司没有业务 |

另行记录来源类型、日期、原文定位、是否直接支持结论、是否有冲突、是否经人工复核。证据过期或冲突可降低可用性，不能自动抹掉历史事实。

如果真实候选池没有“仅表态”等类别，不为凑展示编造公司事实；可另建明确标记的测试夹具验证规则，并与真实研究样本隔离。

## 5. 数据与 AI 方案

### 数据先行

当前没有发现本会话可直接调用的扶摇或 iFinD 工具；尚未验证是否另有账号、接口文档或授权。实施初期设置数据接入检查点，有权限则接入，无权限则采用原题允许的交易所披露、公司官网及权威公开材料，不能将替代数据标注为 iFinD 返回。

优先使用正式公告、年报/季报、监管申报；公司官网产品说明作为业务存在性的补充，不能代替财务收入证据。真实材料和失败/冲突测试数据分别存放。

核心对象：公司、业务环节、证据、数值指标、事件、传导路径、研究版本。每条关键结论绑定证据 ID；指标附带来源、原文位置、报告期、单位、币种与业务范围。

保存必要的短摘录、页码/章节、来源链接与内容摘要校验值，不默认打包整份受版权或授权约束的报告。

### AI 必须有可验证的实际作用

- AI 提取：把新增材料提取为结构化业务事实、待核验指标和候选分类。
- AI 对比：围绕用户选择的两家公司，使用已核验材料生成带引用的可比性解释。
- AI 传导：结合所选事件、公司与证据生成有条件的传导路径。
- 确定性代码负责类型/范围校验、证据 ID 检查、数值计算、分类规则及版本管理；AI 不凭记忆填数字。
- 证据 ID 存在只是第一层校验，还需检查原文是否真正支持该结论；关键种子数据人工核对。
- 模型调用放在服务端，使用环境变量配置，记录模型、提示词版本与运行状态，不把密钥发送给前端。
- 无模型密钥时允许浏览核验后的预置研究，并明确显示预生成/离线状态；不能伪装成实时 AI 调用。最终至少核验一次真实模型链路并记录结果，若接入仍不可用须明确报告交付缺口。
- 对外部材料中的指令当作引用内容处理，限制抓取域名/协议、文本长度、导入格式和调用频率。

## 6. 实现建议

建议采用 TypeScript + React/Next.js 的单项目结构，前后端放在本题目录内，以减少 48 小时内的集成成本。具体版本在初始化时核对，不在规划阶段锁定未经验证的版本。

- 前端：产业环节导航、公司证据抽屉、双公司对照、传导路径和更新历史。
- 服务端：证据检索、模型调用、结构化校验、更新任务与研究版本接口。
- 数据：小规模核验种子数据采用可审计的 JSON；本地持久化可用 SQLite。线上根据实际部署方式使用持久存储或受控版本发布，不依赖临时文件系统保存更新。
- 接口：为公开来源、扶摇/iFinD（若实际可用）、模型分别设置适配层及超时处理。
- 更新写入口受保护；公开访问者可操作研究功能，在隔离演示会话中体验更新，不允许任意访客覆盖共享核验数据。
- 抓取/模型失败时保留上一版并展示失败原因，不生成看似正常的新版本。

## 7. 实施顺序与 48 小时预算

按实际收题时间回推，以下为工程预算，不是当前承诺的完成时刻：

| 阶段 | 预算 | 产物与通过条件 |
| --- | --- | --- |
| 定范围及验证接入 | 4h | 核对接口/模型/部署条件，确定公司池、分类与证据字段 |
| 数据与证据闭环 | 10h | 种子数据、原文定位、至少两组中外比较材料，关键指标人工核验 |
| 可操作主链路 | 12h | 总览、证据、比较、传导页面及真实 AI 服务端调用 |
| 更新闭环 | 8h | 导入、校验、复核、持久化和历史版本；验证一次可追溯变化 |
| 测试与线上验证 | 6h | 主流程/异常测试、实际部署、重新打开线上 URL 验证交互 |

若数据材料耗时超出预算，优先减少公司数量和视觉装饰，保留证据、中外比较、传导、实际 AI 调用与更新五个核心能力。

## 8. 验收与演示

至少验证以下行为，并将实际结果和证据写入现有测试说明：

1. 从环节找到公司，解释归属并打开对应原始材料；数字的报告期、单位和业务范围一致。
2. 对比中外公司，同时展示相似点与至少一个实质不可比项。
3. 为事件生成可追溯路径，区分事实和假设；无证据的节点显式显示不足。
4. 新增/替换一条证据后产生新版本，刷新或重启后仍能读取；旧版本和变更理由可查。
5. 覆盖来源不可用、接口超时、缺失/过期/冲突证据、币种与周期不一致、重复导入、无效模型输出及不存在的引用。
6. 覆盖直接荐股请求、收益承诺、材料提示词注入、恶意导入和未授权写入；客户端及提交物不含密钥。
7. 用浏览器在实际线上地址完成一轮“浏览→比较→传导→更新”，不把构建成功当作交互验收通过。

演示建议约 120 秒：15 秒说明研究问题 → 30 秒展示产业分层及证据 → 25 秒中外比较 → 30 秒传导分析 → 20 秒更新及版本变化。视频展示已实现功能，避免用录屏替代真实产品 URL。
